# 三、判题与安全边界

> 上级：[oj_bank](README.md) · 上一章：[给 AI 的工具](02-ai-tools.md) · 下一章：[洛谷抓题](04-luogu.md)

判题是本插件里唯一**执行别人代码**的动作。这一章说明它怎么判、怎么防、以及
防不住什么。

## 3.1 一个提交经历什么

```text
两步交题：/oj submit 1 cpp  →  下一条消息是代码（文件或文本）
        ↓
取代码：消息里的文件段 / 群文件上传 / 引用的文件 / 文本。
取文件**优先走框架的文件 API**（`FileManager.download_stream` →
NapCat 的 `download_file_stream`，路径 / URL / FileNapCat UUID 都认）；
平台不支持时才退回插件自己取：**http(s) 直连**、或 **`file://` / 本机路径**
（只允许 `submit.local_roots` 下的目录，防止把任意本机文件当代码读）。
        ↓
服务范围白名单（不在白名单：静默丢弃）
        ↓
冷却（judge.cooldown_seconds，防刷）
        ↓
代码审查（review.py：静态规则 → 模型审查）
        ↓ 不通过 → BLOCKED，不落盘、不编译、不运行
落盘 + 编译（g++ -O2 -std=c++17 / gcc / py_compile）
        ↓ 失败 → CE（附编译错误）
逐组运行（每组一个临时文件做 stdin/stdout，时限 + rlimit）
        ↓
比对（忽略行尾空格与末尾空行）
        ↓
计分 + 落库（Submission）+ 回复
```

## 3.2 状态与评分

| 状态 | 含义 | 怎么判 |
|------|------|--------|
| `AC` | 通过 | 全部测试点输出一致 |
| `WA` | 答案错误 | 输出与期望不一致（附「期望 / 实际」预览） |
| `TLE` | 超时 | 墙上时间超限，或 CPU 时间超限（`SIGXCPU`） |
| `RE` | 运行错误 | 非零退出 / 被信号终止 |
| `MLE` | 超内存 | `RLIMIT_AS` 触顶，stderr 出现 `bad_alloc` / `MemoryError` |
| `OLE` | 输出超限 | `SIGXFSZ`，或输出文件超过 `judge.output_limit_kb` |
| `CE` | 编译错误 | 编译器返回非零（Python 是语法检查失败） |
| `BLOCKED` | 审查不通过 | 命中静态规则，或模型判定不安全 |
| `IE` | 判题机错误 | 编译器缺失、工作目录不可写等（不是选手的错） |

**分数**：`100 × 通过组权重 / 总权重`，四舍五入。整题状态取**第一组没过的状态**。

**比对口径**（对齐洛谷）：统一换行符；去掉每行的行尾空格/制表符；去掉末尾多余空行。
中间空行不折叠、行内空格不动。

## 3.3 代码审查

两道闸，缺一不可：

1. **静态规则**（`review.rules`，默认开）：`system()`、`fork()`、`popen`、
   `rm -rf`、读 `/etc/passwd`、`curl | sh`、`import subprocess`、`ctypes`、
   套接字、访问系统路径……这类**竞赛代码里不会出现**的东西直接拦。
   宁可漏，不可误杀 —— 一条误判会让正常题解永远交不上去。
2. **模型审查**（`review.ai`，默认关）：把代码与题名交给 OpenAI 兼容接口，问
   「像不像恶意程序」；返回 `{"verdict":"safe|unsafe","reason":"..."}`。
   结果按 `language+code` 缓存，同一份代码反复提交不重复花钱。

失败口径由 `review.ai.on_error` 决定：

| 值 | 审查服务挂了怎么办 |
|----|--------------------|
| `deny`（默认） | 不判题，回「审查服务不可用」 |
| `allow` | 放行（**不建议**：审查挂了等于没有审查） |

配好才能用：

```json
"review": {
  "rules": true,
  "ai": {
    "enabled": true,
    "base_url": "https://myai.bupt.edu.cn/llm-gw/v1",
    "model": "deepseek-v4-flash",
    "api_key": "sk-...",
    "on_error": "deny"
  }
}
```

密钥也可以走环境变量 `OJ_REVIEW_API_KEY`（优先级更高，别写进仓库）。

## 3.4 安全边界

> ⚠️ 这一节要说清「防住了什么、没防住什么」。把它当沙箱用会出事。

**已经做到的**：

| 面 | 手段 |
|----|------|
| 谁能提交 | `binding` 白名单（群 / QQ，独立绑定，不回落框架 `bound_groups`）；超管豁免，用 `/oj bind` 开通 |
| 恶意代码 | 静态规则 + 模型审查，审不过**不落盘不运行** |
| 死循环 | CPU `RLIMIT_CPU` + 墙上时间超时，超时**杀整个进程组**（fork 出来的孙子也带走） |
| 内存 | `RLIMIT_AS`；Python 在题目内存之外再留 512MB 给解释器本身（不留会在 import 阶段误判 MLE，不留上限则一段大分配能把整机拖进 OOM） |
| 刷屏 | stdout 重定向到文件 + `RLIMIT_FSIZE`，超限判 OLE |
| 写磁盘 | 一次性临时目录，`RLIMIT_FSIZE` 限制它写的任何文件，判完即删 |
| 环境变量注入 | 子进程只给 `PATH` / `LANG` / `HOME` / `TMPDIR` 等死值，不继承机器人环境 |

**没有做到的**：

- **没有网络隔离**：本机禁止 `unshare`（`unshare -n` 直接报错），判题进程仍能联网；
- **没有文件系统隔离**：程序能读机器人用户可读的文件（`RLIMIT_FSIZE` 只限写）；
- **没有降权**：机器人以普通用户运行，无法切换到更低的用户。

因此部署建议：

1. 判题只开给**可信的人**（`/oj bind add user <QQ>` 逐个加，不要图省事放整个群）；
2. 开启模型审查（`review.ai.enabled=true`），`on_error` 保持 `deny`；
3. 不需要判题就关掉：`judge.enabled=false` —— 题库、出图、题组照常工作；
4. 真要多用户开放，把判题进程放进容器 / 独立用户里跑，不要指望这三道闸。

## 3.6 判完之后的 AI 点评

评分发出去之后，后台再问一次模型「这份代码思路是什么、复杂度多少、哪里能改」，
作为**第二条消息**补上：

```text
🧪 #1 A+B Problem · C++17 · 提交 #37
✅ AC · 100 分（10/10 组通过）· 12ms

🧑‍🏫 代码点评（提交 #37）
思路：读入两个整数并输出和。
复杂度：时间 O(1)，空间 O(1)。
改进：1) 用更快的 IO；2) 注意 long long。
```

几条边界：

- **先分数、后点评**：点评是一次模型调用（可能十几秒），同步等会让「交题」看起来卡死；
- **点评失败只少一条消息**：超时 / 限流 / 空响应都不影响分数与提交记录；
- **`BLOCKED` / `IE` 不点评**：代码没跑起来，评设计没有意义；
- 代码只送前 `coach.max_code_chars` 个字符；点评发出去前按 `coach.max_chars` 截断，
  并清掉 Markdown（QQ 不渲染）；
- 同一时刻只跑一条点评（内部串行），不会把判题机压住。

**什么时候点评**：每次判完分（AC/WA/TLE…）自动排一条后台点评，首条是分数、第二条是点评；
状态 `BLOCKED`/`IE`（代码没跑起来）不点评。想补一次用 `/oj coach <提交编号>`。
点评失败（超时、空回复、HTTP 错）会**在聊天里说一句原因**，不再静默；
网关掐断长连接（`ServerDisconnectedError`）会**换连接自动重试一次**。
插件热重载会取消正在跑的点评/生成任务，日志里会写「被取消（插件卸载/重载）」。
qwen 是思考模型：`coach.max_tokens` 默认 **32768**、`coach.timeout` 默认 **300 秒**，
一段复杂代码实测约 2 分钟出点评（后台任务，不影响分数）。

点评用哪个模型：`coach.base_url/model/api_key` **留空时借用 `plugins.ai_chat.llm`**
（同一个网关、同一把 key，不用配两遍）；想换模型或关掉就单独写
`coach.enabled=false` / 覆盖那三项。

> ⚠️ **代码会发给点评模型**（与 ai_chat 同一个网关，可能是外部服务）。
> 不想让代码离开这台机器就 `coach.enabled=false`；判题本身不联网。

## 3.5 排查

| 现象 | 原因 / 处理 |
|------|-------------|
| `IE`：服务器上没有 g++/gcc | `apt install build-essential`，或只开 Python |
| `CE` 但本地能编过 | 判题用 `-O2 -std=c++17`；检查是不是用了 `-std=c++20` 语法 |
| 一直 `TLE` 但本地很快 | `time_limit_ms` 是**毫秒**；题目导入时可能带的是洛谷的时限 |
| `BLOCKED` 但代码正常 | 看 `reason` 命中了哪条规则；规则表在 `review.RULES`，可关 `review.rules` |
| 判题很慢 | `judge.max_concurrent` 默认 1，一次只跑一份；10 组 × 1s 上限 ≈ 10s |
| 出图报 Chromium | 与判题无关，见 [出图](06-render.md) |
