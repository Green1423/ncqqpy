# 八、测试点从哪来（AI 生成）

> 上级：[oj_bank](README.md) · 上一章：[代码结构与测试](07-structure.md)

评分靠测试点，而**洛谷页面上没有测试数据**、AI 搜来的题也不自带。题库里的
卡人测试点有两个来源：

| 来源 | 谁写 | 适合 |
|------|------|------|
| 工具 `oj_bank_cases` / 命令 | 模型或人**直接写** input + output | 你手上有确定的答案 |
| 工具 `oj_bank_generate_cases` / `/oj gen` | **插件让 AI 出题**，输出由参考解跑出来 | 想要一套完整的卡人数据 |

推荐后者：模型手算的期望输出经常是错的，而判题逐字节比对 —— 一条错的期望输出
会把正确题解判成 WA。

## 8.1 AI 生成的流程

```text
/oj gen 7            # 或工具 oj_bank_generate_cases(problem_id=7)
        ↓
模型返回 JSON：{ language, reference（参考解源码）, cases:[{input, note}] }
        ↓
① 参考解先跑**官方样例** —— 过不了整批作废（模型连样例都没过，后面不用信）
        ↓
② 参考解逐组跑这些输入，**它的 stdout 就是标准输出**
   （参考解自己 RE/TLE 的那组直接丢掉）
        ↓
③ 写进题库（默认替换旧的卡人测试点），最多 10 组
```

所以入库的是「**参考解算得出的**期望输出」，正确性与参考解同一水平，而不是与
模型的算术同一水平。

```text
/oj gen 7
⏳ 正在让 AI 出测试点（先跑参考解验证，可能一两分钟）…
✅ 已生成 9 组测试点（#7 砍树，参考解 C++17，输出由参考解跑出）
现在卡人测试点 9/10 组
参考解跑挂、已丢弃：第 6 组（TLE）
```

## 8.2 命令与工具

| 入口 | 说明 |
|------|------|
| `/oj gen <编号> [数量]` | 生成（1..10 组，默认 10）；先回一句「正在出」，结果随后发 |
| 工具 `oj_bank_generate_cases` | `problem_id` / `count` / `replace`，AI 在对话里可以直接调 |

生成会**替换**旧的卡人测试点（`replace=true`）。想保留人工写的几组，就先用
`/oj cases <编号>` 看一眼，或者生成后手动补。

## 8.3 配置

```json
"gen": {
  "enabled": true,
  "count": 10,
  "timeout": 180,
  "max_tokens": 4096,
  "max_statement_chars": 6000,
  "max_input_chars": 20000,
  "base_url": "",
  "model": "",
  "api_key": "",
  "reasoning_effort": ""
}
```

- `base_url/model/api_key` 留空时**借用 `plugins.ai_chat.llm`**（同一个网关）；
  密钥也可用环境变量 `OJ_GEN_API_KEY`；
- `max_tokens` 要够写一份参考解 + 10 组输入（默认 4096，模型爱思考就调大）；
- `timeout` 是整次生成的超时（模型 + 跑代码）；
- 不想让代码/题面离开这台机器，就 `gen.enabled=false`，测试点改用
  `oj_bank_cases` 手写。

## 8.4 失败时

| 现象 | 原因 / 处理 |
|------|-------------|
| `❌ 生成失败：模型没有输出 JSON` | 模型没按要求输出；换模型或调大 `max_tokens` |
| `❌ 生成失败：超时` | 题面太长 / 模型太慢；调大 `gen.timeout`，或换更快的模型 |
| `❌ AI 给的参考解过不了官方样例` | 参考解是错的；重试一次或换更强的模型（`gen.model`） |
| `❌ 参考解在这些输入上全部失败` | 生成的输入超出了参考解的能力（超时/段错误）；重试 |
| `参考解跑挂、已丢弃：第 N 组` | 部分输入不可用，其余照常入库 |

> ⚠️ 生成的测试点**只和参考解一样可靠**。重要比赛用之前，建议自己写一份
> 独立解法对拍一遍（`/oj submit` 交你自己的解，看是否 AC）。
