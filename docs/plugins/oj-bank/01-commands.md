# 一、命令

> 上级：[oj_bank](README.md) · 下一章：[给 AI 的工具](02-ai-tools.md)

前缀取自 `config.json` 的 `command_prefixes`（默认 `/` 和 `#`）。用法行里的
`<必填>` / `[可选]` 是占位符，尖括号本身不用输入。群里需要先 @机器人。

## 1.1 命令表

| 命令 | 说明 |
|------|------|
| `/oj luogu <题号>` | 抓洛谷题目入库（题干 / 输入输出格式 / 样例 / 时限内存） |
| `/oj show <编号>` | 题目渲染成图片发出来 |
| `/oj list [关键词] [--page=N]` | 题库列表（编号 / 标题 / 来源 / 难度 / 测试点数） |
| `/oj submit <编号> [语言] [代码]` | 判题；不带代码时进入「下一条消息是代码」 |
| `/oj cancel` | 取消等待中的代码 |
| `/oj result [提交号]` | 判题详情；不给提交号 = 自己最近一次 |
| `/oj cases <编号> [list\|clear]` | 看测试点（含每组「卡什么」）/ 清空（仅超管） |
| `/oj gen <编号> [数量]` | 让 AI 出一套卡人测试点（输出由参考解跑出，见 [第八章](08-testcases.md)） |
| `/oj set <动作> [组名] [题号...]` | 题组，见 1.4 |
| `/oj del <编号>` | 删题（仅超管） |

`<编号>` 可以是**题库编号**（`12`），也可以是**洛谷题号**（`P1001`）—— 抓过的题
两种写法都能用。

## 1.2 抓题与看图

```text
/oj luogu P1001
✅ 已入库 #1 A+B Problem（难度 入门，1 组官方样例）
💡 只有官方样例，还不能评分：让 AI 用工具 oj_bank_cases 生成 10 组卡人测试点。

/oj show 1
（图片：题名、难度、时限内存、题目描述、输入格式、输出格式、输入样例、输出样例、注意事项）
```

洛谷页面上**没有**官方测试数据，所以抓来的题只有样例。要评分得补测试点：
让 AI 用 `oj_bank_cases` 生成，或把 `max_cases` 内的测试点手工维护。

## 1.3 交题（发代码文件）

```text
/oj submit 1 cpp
📥 把代码文件发上来（C++17，10 分钟内有效）：
· 私聊：直接发文件（.cpp / .c / .py）；
· 群聊：传到群文件（群里发文件走群文件上传）；
· 也可以直接发代码文本，或引用一条代码消息再发 /oj submit；
· 发别的 /oj 命令或 /oj cancel 取消。

（发送 main.cpp）
🧪 #1 A+B Problem · C++17 · main.cpp · 提交 #37
✅ AC · 100 分（10/10 组通过）· 412ms
1✅  2✅  3✅  4✅  5✅
```

**为什么走文件**：命令解析器会处理引号与 `\n`、`\t` 这类转义，长代码里的反斜杠
很容易被改坏；文件是字节流，一个字符都不动。语言还能按**后缀**判断 ——
`sol.py` 会以 Python 3 交，即使命令里写的是 `cpp`。

四种交法都能用：

| 方式 | 怎么发 |
|------|--------|
| 命令消息带文件 | `/oj submit 1` 并把 `.cpp` 作为附件一起发 |
| 引用文件 | 引用一个代码文件，再发 `/oj submit 1` |
| 两步（推荐） | 先 `/oj submit 1 cpp`，再把文件发上来（私聊直接发 / 群里传到群文件） |
| 贴文本 | `/oj submit 1 py print(sum(map(int,input().split())))` |

文件上限 `judge.max_file_kb`（默认 64KB）；二进制文件、图片会被拒收。
传错文件不会消耗本次等待 —— 再发一个正确的就行。

## 1.4 题组

题组是**有序的题目集合**，可以出图、出榜单：

| 命令 | 说明 |
|------|------|
| `/oj set new <组名> [标题]` | 新建（已存在则更新标题） |
| `/oj set add <组名> <题号...>` | 加题（重复的自动跳过） |
| `/oj set remove <组名> <题号...>` | 移出 |
| `/oj set show <组名>` | 题组图（题单） |
| `/oj set list` | 全部题组 |
| `/oj set rank <组名>` | 榜单：每题取历史最高分，总分 = 满分 × 题数 |
| `/oj set del <组名>` | 删除（仅超管） |

榜单口径：每人每题取**历史最高分**；没交过的题按 0 分计入分母（分母固定，
只交简单题刷不了排名）。同分看 AC 数。

## 1.5 谁能用（服务范围绑定）

配置在 `plugins.oj_bank.binding`。命令与 `empty_means` 跟 `ai_chat` 一致，
但群名单**独立**（不回落框架的 `bound_groups`）：

| 层 | 判据 |
|----|------|
| 群 | `binding.groups`（**只看这一份，不回落框架的 `bound_groups`**） |
| 私聊 / 小窗 | `binding.users`（小窗按来源群判） |
| 两边都空 | 按 `empty_means`：`deny`（默认，谁都不用）/ `allow` |

**超级用户不豁免**：服务范围是运维决策，不是权限决策 —— 超管在没开通的群里
同样用不了。唯一的例外是**管理绑定本身的命令**（否则名单为空时永远开不出
第一条）：

```text
/oj bind list                  # 看当前服务范围（仅私聊 + 超管）
/oj bind add group 123456789   # 开通一个群
/oj bind add user 10001        # 开通一个私聊（省略号 = 自己）
/oj bind del group 123456789   # 停用
```

- 改完立即生效，并写回 `config.json → plugins.oj_bank.binding.*`；
- 名单只有插件这一份：加 / 删就是对 `binding.groups` / `binding.users` 的直接
  增删（框架的 `bound_groups` 是「监听哪些群」，与「允许哪些群用」无关）；
- 范围外的聊天**完全静默**：不回「没开通」、`/help` 里也看不到 `/oj`
  （超级用户的 `/help` 始终可见，部署时正是最需要它的时候）。
